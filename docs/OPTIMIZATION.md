# Bronze Ware Interaction 优化记录

本文件记录当前版本针对加载速度、手势稳定性、渲染性能和工程维护所做的优化。

## 1. MediaPipe 稳定性

- MediaPipe Vision 模块提供 jsDelivr 与 unpkg 两个回退地址。
- 手势模型提供 float16 与 int8 两个回退地址。
- 摄像头 API 不可用、权限拒绝、模型下载失败时会自动回到鼠标模式。
- 手势加载状态和失败原因会显示在页面状态栏中。

由于 MediaPipe 官方运行时和 WASM 文件体积较大，当前先采用 CDN 回退策略，避免继续增加仓库体积。后续如果需要完全离线运行，可将这些资源放入 `public/vendor/mediapipe/`，再把地址加入 `MEDIAPIPE_SOURCES`。

## 2. 模型按需加载

- 首屏只加载第一个模型。
- 其他模型在用户切换时加载，并通过 `modelLoading` 合并重复请求。
- 已加载模型按最近使用时间缓存，最多保留三个模型。
- 被淘汰的模型会从场景移除并释放几何体、材质和纹理资源。

## 3. 粒子采样缓存

模型粒子采样结果会写入 IndexedDB。缓存键包含版本号、粒子数量和模型 URL，避免旧数据与新算法混用。首次处理模型仍会有计算成本，之后再次打开页面会直接复用采样结果。

## 4. 音乐懒加载

背景音乐设置为 `preload="none"`，只有用户点击播放按钮后才请求 MP3，减少首屏网络和内存压力。

## 5. 自适应粒子数量

网页根据 `navigator.deviceMemory` 与 `navigator.hardwareConcurrency` 选择粒子纹理尺寸：高性能桌面使用 65,536 个粒子，低端设备使用 36,864 个粒子。

## 6. 页面生命周期

页面进入后台时暂停动画帧、手势检测和摄像头视频轨道；返回页面后自动恢复，减少后台 CPU/GPU 占用。

## 7. WebGL 恢复

监听 WebGL 上下文丢失与恢复事件。恢复成功后会重建 GPGPU 粒子引擎，失败时保持实体模型作为降级方案。

## 8. 加载体验

全屏加载层不再等待全部模型和粒子引擎。首个模型准备完成后立即进入交互界面，剩余模型在后台按需准备；状态栏会显示当前资源状态。

## 9. 工程结构

当前项目保持 GitHub Pages 的零构建入口，交互网页仍由 `index.html` 直接运行。运行时配置、优化记录和资源说明已独立归档，后续可按以下边界拆分：

```text
src/
├── main.js       # 启动、生命周期与路由
├── scene.js      # Three.js 场景和实体模型
├── particles.js  # GPGPU 粒子系统
├── gesture.js    # MediaPipe 与手势状态机
└── ui.js         # 双语 UI 与状态提示
```

在当前无构建工具的 GitHub Pages 项目中直接拆分模块会增加部署路径和 MIME 类型风险，因此本轮先完成运行时边界、配置文档和资源管理；拆分时应配套 `package.json`、本地预览和 CI 检查。

## 10. 部署检查清单

- GitHub Pages 来源为 `main` 分支根目录。
- 入口为 `/index.html`。
- 模型、音乐、JSON 和本地 Three.js 资源均使用相对路径。
- 每次修改后检查 `git diff --check`、ES Module 语法和线上资源状态。
- 摄像头手势必须在 HTTPS 页面并获得用户授权后启动。
